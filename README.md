# make-knowledge-cards 知识卡片生成器

一个开源的 Trae Skill，把用户粘贴的文章或本地 Markdown / TXT 文件转换成 5~8 张结构化知识卡片，便于学习、复习和分享。

## 项目解决什么问题

学生在读长文章、看网课笔记、翻教辅时常常遇到两个痛点：

1. **读完就忘**：一篇文章几千字，读完当时懂了，过两天脑子里只剩个模糊标题，没有可复习的抓手。
2. **笔记冗长低效**：很多人做笔记等于抄书，几十页看下来重点反而被淹没，复习时还得再筛一遍。

本 Skill 把任意一篇文章**自动提炼**为一组独立、精炼的知识卡片，每张卡片只讲一个知识点，并附带例子或自测题，直接可以作为复习和自测的素材。

**适用人群**：高中生、大学生、自学者、任何需要把长文压缩为可复习知识点的人。

**暂不支持**：网页抓取、PDF、Word 等二进制格式、Anki / SuperMemo 格式导出、图形界面。遇到这些情况请先转换为 Markdown / 纯文本再使用。

## 主要功能

### 核心能力

把一篇文章提炼为一组知识卡片，每张卡片包含四个固定字段：

| 字段 | 内容要求 | 长度建议 |
|------|----------|----------|
| **标题** | 一句话概括本卡片的知识点，清晰具体 | 10~30 字 |
| **核心知识** | 原文中的核心结论、定义或规则，准确提炼不添加主观判断 | 30~100 字 |
| **简明解释** | 补充说明重要性、适用条件、上下文，必须基于原文不可发挥 | 50~150 字 |
| **例子或自测问题** | 原文出现过的例子，或一道能从原文推出答案的自测题 | 30~100 字 |

### 设计原则

- 提取真正重要的知识，不做文字搬运
- 一张卡片只讲一个知识点
- 删除重复、冗余的表述
- 不编造原文没有的信息、例子、数据
- 信息不足时不强行凑数，高质量 3 张卡远胜注水 8 张

### 内置质量自检

Skill 在输出前会逐条核对五项清单，不满足的会自动修改或删除：

- 信息来源：核心知识是否在原文中有明确依据
- 单一性：这张卡片是否只讲了一个知识点
- 无编造：例子或自测题是否原文有或能严格推出
- 去重复：与其他卡片是否有内容重叠
- 完整性：四个字段是否都填了

### 辅助工具：quick_validate.py

项目根目录提供一个零依赖的 Python 验证脚本，用于检查 Skill 文件是否符合规范：

- 检查 `SKILL.md` frontmatter 格式、必填字段、允许的 key
- 检查 `name` 命名规则（hyphen-case、长度 ≤64）
- 检查 `description` 长度（≤1024）和非法字符
- 检查 `agents/openai.yaml` 的 `interface` 三字段（display_name / short_description / default_prompt）
- 检查 `short_description` 长度区间（25~64）
- 检查 `default_prompt` 是否显式引用技能名标记 `$skill-name`
- 自实现递归 YAML 解析器，支持任意层级的 `key: |` 多行字面量，无需安装 PyYAML

## 安装方法

### 前置要求

- [Trae](https://trae.cn/) IDE（已内置 Skill 运行时）
- Python 3.7+（仅运行 `quick_validate.py` 验证脚本时需要；正常使用 Skill 不需要）

### 把 Skill 加入到你的环境

本 Skill 符合 Trae / OpenAI 的标准 Skills 目录结构。把 `skills/make-knowledge-cards/` 目录复制到你项目的 `skills/` 或 `.trae/skills/` 目录下即可被 Trae 自动识别：

```bash
# 假设你要把它放到自己的项目里
cp -r skills/make-knowledge-cards /path/to/your/project/.trae/skills/
```

无需 `npm install`、无需 `pip install`，Skill 定义本身是纯文本。

## 使用方法

### 在对话中使用

当你需要把一篇文章做成知识卡片时，直接对 Trae 说：

```
请用 make-knowledge-cards 技能，把这篇文章做成知识卡片：
<在此粘贴文章内容>
```

或者提供本地文件路径：

```
把 D:\notes\RAG-intro.md 转成知识卡片。
```

Trae 会自动加载本 Skill，并按其中定义的六步流程执行：

1. 获取并理解内容（文件用 `Read` 读取，粘贴文本直接处理）
2. 提取真正重要的知识（严格筛选，不编造）
3. 拆分知识点（一张卡片只讲一个点，总数 5~8 张）
4. 为每张卡片填充四个字段（标题 / 核心知识 / 简明解释 / 例子或自测问题）
5. 质量自检（信息来源 / 单一性 / 无编造 / 去重复 / 完整性）
6. 按规定 Markdown 格式输出

### 验证 Skill 格式

项目根目录提供了 `quick_validate.py` 脚本，用于检查 Skill 文件是否符合规范：

```bash
python quick_validate.py skills/make-knowledge-cards
```

通过时会输出：

```
✅ Skill validated successfully — Skill is valid!
```

如果格式有问题，会列出具体错误，例如：

```
❌ Validation failed for 'skills/make-knowledge-cards':
- interface.short_description 太短（当前 10，最少 25）
- interface.default_prompt 应显式引用技能名标记 $make-knowledge-cards
```

### 输出后导出为文件

生成卡片后，如果想保存为 Markdown 文件，直接对 Trae 说：

```
把这份知识卡片导出为 Markdown 文件，保存到 D:\notes\卡片.md
```

Trae 会用 `Write` 工具把内容写入指定路径。

## 输入输出示例

### 示例 1：粘贴文本输入 → 知识卡片输出

#### 输入（粘贴的科普短文片段）

```
植物的光合作用

光合作用是绿色植物、藻类和某些细菌利用太阳光能，把二氧化碳和水转化为储存着化学能的有机物（主要是葡萄糖），并释放氧气的过程。

总反应式可以概括为：6CO2 + 6H2O + 光能 → C6H12O6 + 6O2。

真核生物中，光合作用发生在叶绿体里。叶绿体含有类囊体薄膜堆叠而成的基粒，上面分布着叶绿素等色素，负责捕获光能；叶绿体基质则是暗反应的场所。

光反应必须在光下进行：水分子被分解，释放出氧气，同时产生 ATP 和 NADPH。
暗反应（卡尔文循环）不需要光直接参与，但需要光反应提供的 ATP 和 NADPH。
```

#### 输出（5 张知识卡片）

```markdown
# 知识卡片

共 5 张卡片，来源：用户粘贴文本

## 卡片 1

### 标题
光合作用的定义与总反应式

### 核心知识
光合作用是绿色植物等把 CO2 和 H2O 在光能下转化为葡萄糖并释放 O2 的过程，总反应式为 6CO2 + 6H2O + 光能 → C6H12O6 + 6O2。

### 简明解释
反应的本质是把无机物变成储存能量的有机物，同时把光能转为化学能储存在葡萄糖中。产物里的氧气来自水的分解，葡萄糖里的碳和氧则来自二氧化碳和水。

### 例子或自测问题
自测题：光合作用生成的 O2 来自反应物中的哪种分子？（答案：来自水，不是来自 CO2）

## 卡片 2

### 标题
真核生物光合作用的场所：叶绿体

### 核心知识
真核生物中光合作用发生在叶绿体，类囊体薄膜（基粒）上的色素捕获光能，叶绿体基质是暗反应场所。

### 简明解释
叶绿体有两类关键结构：类囊体叠成的基粒，上面分布着叶绿素和类胡萝卜素，直接吸收光能；以及充满液态的基质，含有参与卡尔文循环的酶。蓝藻等原核生物没有叶绿体，但有叶绿素和相关酶，在细胞质中直接进行。

### 例子或自测问题
自测题：原核生物蓝藻是否能进行光合作用？它有叶绿体吗？（答案：能进行光合作用，但没有叶绿体，光合结构位于细胞质中）

## 卡片 3

### 标题
光反应：必须有光才能进行

### 核心知识
光反应发生在类囊体薄膜，需要光照；产物是 O2、ATP 和 NADPH；氧气来源于水的分解。

### 简明解释
光反应是能量转换的第一步：光能被色素吸收后，激发电子传递链，把水分解为 H+、电子和氧气，同时合成 ATP 和 NADPH 两种能量载体。这些产物随即进入暗反应，所以没有光时暗反应很快因为缺能量而停转。

### 例子或自测问题
例子：把一株植物放在完全黑暗中，它虽然理论上仍可"暗反应"片刻，但用光反应积累的能量耗尽后，光合作用整体就立刻停止了。

## 卡片 4

### 标题
暗反应（卡尔文循环）：不直接需要光，但依赖光反应产物

### 核心知识
暗反应在叶绿体基质中进行，固定 CO2 并逐步还原为葡萄糖；必须使用光反应产生的 ATP 和 NADPH。

### 简明解释
暗反应是"合成有机物"的步骤：CO2 与体内的五碳化合物结合（被固定），再经过一系列酶促反应（卡尔文循环），利用 ATP 供能和 NADPH 还原力，最终生成葡萄糖。它不需要光直接照射，但每一步都需要光反应持续供给能量。

### 例子或自测问题
自测题：为什么"暗反应"不等于"只在黑暗中发生"？（答案：暗反应不直接依赖光，但必须不断消耗光反应产生的 ATP 和 NADPH，所以通常在有光时持续进行）

## 卡片 5

### 标题
光合作用的生态意义

### 核心知识
光合作用是地球上几乎所有有机物和氧气的最终来源，维持大气 O2/CO2 平衡，是生态系统能量流动的起点。

### 简明解释
绝大多数异养生物（包括人类）的食物直接或间接来自植物制造的有机物；大气中的氧气主要靠光合补充，同时吸收 CO2 缓冲温室效应。整个生态系统的能量流动起点是生产者（植物等）通过光合作用固定的太阳能。

### 例子或自测问题
自测题：如果地球上的绿色植物突然全部消失，大气成分和食物链会分别发生什么核心变化？（答案：氧气逐渐耗尽、CO2 持续升高；食物链从生产者开始崩溃，几乎所有高等生命都无法维持）
```

### 示例 3：边界情况

| 输入情况 | 处理方式 |
|----------|----------|
| 原文极短（< 100 字） | 告知用户内容太少，建议提供更详细的文章 |
| 原文是代码或纯技术命令 | 可以做，但每张卡片聚焦一个技术点，例子字段用代码片段 |
| 用户要求特定卡片数量 | 如在 5~8 范围内则满足，超出范围的说明默认是 5~8 张并按默认执行 |
| 用户提到 Anki / SuperMemo | 明确告知暂不支持导出为 Anki 格式，先按 Markdown 卡片输出 |
| 用户提供 PDF / 网页链接 | 明确告知暂不支持网页抓取和 PDF，建议用户先复制内容粘贴或保存为 .md / .txt |
