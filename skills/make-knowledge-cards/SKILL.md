# Make Knowledge Cards 知识卡片生成器

## 描述

将文章或文本内容提炼为 5~8 张独立的知识卡片，每张卡片聚焦一个核心知识点，便于复习、记忆和分享。

## 使用场景

当用户出现以下意图时调用本技能：
- "帮我把这篇文章做成知识卡片"
- "把这个笔记整理成学习卡片"
- "制作几张知识卡片"
- "把这个 Markdown 文件转成卡片"
- 用户提供文章/文件，明确要求提炼知识点或制作自测题

## 输入接受方式

支持两种输入，优先按以下顺序判断：

1. **本地文件路径**：用户提供 `.md` 或 `.txt` 文件的路径
   - 用 `Read` 工具读取文件内容
2. **直接粘贴的文本**：用户在对话中直接粘贴文章内容

暂不支持：网页抓取、PDF、Word 等二进制格式。遇到这些请告知用户先转换为 Markdown/TXT 后再试。

## 核心指令（必须严格遵守）

### 第一步：获取并理解内容

- 如果是文件路径，先读取文件完整内容
- 通读全文，识别文章的主题和结构

### 第二步：提取真正重要的知识（严格筛选）

筛选标准：
- 只提取**原文明确陈述**的核心概念、原理、结论、关键规则
- **严禁编造**原文没有的信息、例子、数据
- 删除重复、冗余的表述
- 优先选择：定义、核心原则、关键步骤、常见误区、重要结论
- 对于信息不足的短文，**不要强行凑数**，产出 3-4 张高质量卡片也好过 8 张注水卡片

### 第三步：拆分知识点（一张卡片只讲一个点）

拆分规则：
- 将提取的知识点拆分为独立单元，每张卡片**只讲一个知识点**
- 不要把多个独立概念塞进同一张卡片
- 总卡片数量控制在 **5~8 张**；如果原文内容特别少，允许少于 5 张（但不应出现 0 张或 1 张）；如果原文内容非常丰富，最多不超过 8 张，优先保留最重要的

### 第四步：为每张卡片填充四个字段

每张卡片必须且只能包含以下四个部分，字段名固定为中文：

| 字段 | 内容要求 | 长度建议 |
|------|----------|----------|
| **标题** | 用一句话概括本卡片的核心知识点，清晰具体，不笼统 | 10~30 字 |
| **核心知识** | 用 1-2 句陈述原文中的核心结论、定义或规则，必须是原文的准确提炼，不添加主观判断 | 30~100 字 |
| **简明解释** | 对核心知识做进一步的补充说明：为什么重要、适用条件、注意事项、上下文背景。解释必须基于原文，不可发挥 | 50~150 字 |
| **例子或自测问题** | 二选一：要么给一个**原文出现过**的例子帮助理解，要么出一道自测题（选择题/判断题/简答题均可），自测题的答案必须能从原文推导 | 30~100 字 |

### 第五步：质量自检（输出前必须逐条检查）

输出前对每张卡片检查以下清单，不满足的必须修改或删除：

- [ ] 信息来源：核心知识是否在原文中有明确依据？没有就删掉这张
- [ ] 单一性：这张卡片是否只讲了一个知识点？否则拆分
- [ ] 无编造：例子或自测题是否是原文有的或能严格从原文推出？否则重写
- [ ] 去重复：与其他卡片是否有内容重叠？合并或删掉冗余的
- [ ] 完整性：四个字段是否都填了？空缺的补上

### 第六步：输出格式

使用 Markdown 格式输出，每张卡片用二级标题（`## 卡片 N`）分隔，四个字段用三级标题（`### 标题` 等）标识。

**输出模板（严格按此格式）：**

```markdown
# 知识卡片

共 N 张卡片，来源：<文件名或"用户粘贴文本">

## 卡片 1

### 标题
<标题内容>

### 核心知识
<核心知识内容>

### 简明解释
<解释内容>

### 例子或自测问题
<例子或自测题，若为自测题请在末尾用括号标注答案提示：如 "（答案：见卡片核心知识）">

## 卡片 2
...
```

## 边界情况处理

| 情况 | 处理方式 |
|------|----------|
| 原文极短（< 100 字） | 告知用户内容太少，建议提供更详细的文章 |
| 原文是代码或纯技术命令 | 可以做，但每张卡片聚焦一个技术点，例子字段用代码片段 |
| 用户要求特定卡片数量 | 如在 5~8 范围内则满足，超出范围的说明默认是 5~8 张并按默认执行 |
| 用户提到 Anki/SuperMemo | 明确告知暂不支持导出为 Anki 格式，先按 Markdown 卡片输出 |
| 用户提供 PDF/网页链接 | 明确告知暂不支持网页抓取和 PDF，建议用户先复制内容粘贴或保存为 .md/.txt |

## 示例（仅展示格式，具体内容以实际输入为准）

> 以下为格式示例，**实际执行时必须基于用户提供的真实内容，不可照抄示例**。

假设输入是一篇关于"RAG 检索增强生成"的文章摘要，输出如下：

```markdown
# 知识卡片

共 5 张卡片，来源：用户粘贴文本

## 卡片 1

### 标题
RAG 的定义与核心作用

### 核心知识
RAG（检索增强生成）是将外部知识库检索与 LLM 文本生成相结合的技术，用于提升回答准确性、减少幻觉。

### 简明解释
LLM 自身只有训练时的参数记忆，无法获取实时或私有数据。RAG 在生成答案前先从外部库检索相关文档，将其拼接进上下文，让模型基于真实资料作答。

### 例子或自测问题
自测题：RAG 主要解决 LLM 的哪两个典型问题？（答案：回答不准确、编造事实即幻觉）

## 卡片 2

### 标题
RAG 的标准流程三步骤

### 核心知识
RAG 的标准流程为：用户提问 → 向量化后检索 Top-K 相关文档 → 拼接上下文送入 LLM 生成答案。

### 简明解释
三个步骤缺一不可。向量化是把文本转为向量以便语义匹配；Top-K 是控制返回的文档数量（通常 3-5），太少不够、太多噪声；拼接上下文让模型在生成时能看到检索结果。

### 例子或自测问题
例子：用户问"今年财报营收多少"，RAG 先检索财报 PDF 对应段落，再让 LLM 基于段落给出数值。
```
